# Seeds: the designs' content in the local database

The app reads the portal's real API. A fresh local database has none of the people, events, photos and prices in the design PNGs, so against it the app looks different from them even though every screen is built to the PNGs (run it with `--dart-define=FEED_SOURCE=demo` to see the exact content, bundled in the app). These scripts fill the **local** database with the designs' content so the live app reads like the PNGs too.

**Local only.** Each script refuses to run unless `DATABASE_URL` in `irc-portal/backend/.env` points at localhost, and unless the working directory is `irc-portal/backend`. Never point them at a shared or production database: they invent accounts.

## Run

```
powershell -File tool\seed\run.ps1            # all of them, idempotent
powershell -File tool\seed\run.ps1 -Remove    # takes it all out again
```

Or one at a time, from `E:\ICR\irc-portal\backend` (Git Bash; in PowerShell set `$env:NODE_PATH` first):

```
NODE_PATH=E:/ICR/irc-portal/node_modules npx ts-node --transpile-only E:/ICR/icr-mobile/tool/seed/<script>.ts [--remove]
```

Run the portal's own seeds first if the database is new: `db:seed:test-users`, `db:seed:mentorship`, `db:seed:association` (the councils and events these scripts build on). The API does not need a restart.

## Things to know

- The e2e suite shares these personas and the same tables: counts and screenshots of the job board, events, councils and the mentor directory (now 64 listed mentors) will differ while the seeds are in. Run with `-Remove` first for an e2e run.
- The local database has no pgvector, so the portal's match scorer (`GET /jobs/:id/match-preview`) answers 500 for anyone with a résumé. The app copes (the job sheet shows the résumé-skills card instead), but it is why "92% Profile Match" reads 95%.
- The counts the Home design shows are reached **as far as the accounts allow**: a person reacts and votes once, so the design's 184 reactions are reachable here (there are about 190 accounts that may react) but the poll's 842 votes are not: it holds one vote per account (192 here), in the design's 28 / 14 / 46 / 12 split. The design's "14 shares" has no counterpart (the API counts no shares), so the card prints the discussion's views there.
- Home's "Reply to Priya Nambiar..." box, "+8 replies in this thread" pill and the 42 minutes beside Arvind Swamy's reply read as the design because of what `home.ts` writes (the newest reply is Priya's; the first reply's thread has nine more), and the minutes, hours and days beside each post are relative to **when the seed last ran**: run it again to bring "2h ago" back.
- Some of the designs' details cannot come from the API: "RICS Accredited", the "1,420 attendees" (the count is the number of accounts that exist), pass numbers and QR codes, the company tagline, applicant counts. They are listed per screen in `docs/screens/`.
- `tsconfig.json` and `assets/` here are used by the scripts (ts-node looks for a tsconfig beside the script; `assets/course_cover_clean.png` is the design's course thumbnail without its baked-in label).
