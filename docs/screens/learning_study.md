# Learning: Flash Cards and the Knowledge Center (STUDY)

The two doors of the Learning hub that are about **studying**: `Flash Cards` (`/learning/flash-cards` on the website) and `Knowledge Center` (`/learning/formulas`). There is no PNG for either: the reference is the website's Resource Center (`ResourceCenterLanding`, `ResourceTopicCards`, `FlashcardDeck`, `FlipCard`, `FormulaCard`, `FormulaDialog`, `MathFormula`, `formula.ts`) drawn the way a phone draws the same content and the same steps, on the app's own frame (white cards, a 1 dp slate edge, 12 dp corners, Work Sans titles, IBM Plex Sans body, `lib/features/learning/widgets/course_card.dart`'s grid).

**A deck goes with an Assess your knowledge course (owner's call, 27 Oct 2026: "a course and its flash cards are one thing").** A deck whose title matches a course's is *linked* to it (`LearningResourceTopic.courseId`; staff link or unlink in the shelf editor; the migration linked every deck with a matching title). A linked deck is **open exactly when its course is**: opened with one of the plan's places, or any level of it redeemed with ICR credits or bought, or the plan opens everything. It takes **no deck place of its own**, so opening or buying the course opens the deck of the same name, and the same sale on the Assess screens (a level redeemed, a place used, the bundle) unlocks its flash cards at once. A deck on its own (no course) still counts against the plan's number of decks, as before. The API decides at every read (`403 DECK_LOCKED`); the grid's marks are a preview of its answer (`DeckPlan.stateFor`), proved against the real API by `test/live/learning_study_live_test.dart`. An API from before that change sends no `courseId`: every deck is then on its own and nothing below changes.

Both are the website's **Resource Center** read two ways: a shelf (`LearningResourceTopic`) is either a flash-card deck (`kind QNA`, about 200 cards each locally) or a group of formulas (`kind FORMULA`, 15 to 25 each); a card has a `front` and a `back`. Everything below is under `lib/features/learning_study/`.

## How the screens are wired

The hub pushes `FlashCardsScreen` / `KnowledgeCenterScreen` (`AppShell.push(... ShellPage(tab: AppTab.learning, child: ...))`). Each builds its own controller and repository in `initState` (`AppConfig.demo ? DemoStudyRepository() : ApiStudyRepository(api: context.read<ApiClient>())`) because a pushed route does not inherit the tab's providers. The constructors are the stubs' (`onBack`); an optional `repository` is for tests. `pubspec.yaml` gained one dependency, **`flutter_math_fork: ^0.7.4`** (the KaTeX port the Knowledge Center draws math with; it brings `tuple`).

The older text below describes the plan before decks followed courses. **Bharat Buyer's and Pooja Professional's plans give 0**, so for them every deck is **Locked** ("Flash cards are not included in your plan.") and the API refuses a deck and a star. That is the product's real behaviour (the website marks the same tiles LOCKED) and the app shows it. The formulas need no plan. To study a deck locally, sign in as **`study.cards@learning-study.icr.test` / `Study@12345`** (`tool/seed/learning-study.ts`: three places), or run the seed with `--grant-bharat` (see `tool/seed/README.md`: it also changes his Assess your knowledge locks, so it is off by default).

Opening a deck on its own, or a course, takes a place **for good**; the API has no way to give one back (the study persona's live tests open the courses of the first three linked decks, once; `tool/seed/learning-study.ts --remove` forgets them). The grid does not ask first (the website does not either); the line over it says how many are used.

## How a formula is read and drawn (`study_format.dart`, `widgets/formula_math.dart`)

A formula card stores its expression first and, after a blank line, an optional note: `$$PV = FV\div (1+r)^{n}$$` then `PV=Present Value`… (the website's `formula.ts`). The editors type **words without `\text{}`**, and zero-width spaces and `×`/`÷`/`−` as characters, so KaTeX on the website draws "PortfolioOccupancy=OccupiedArea÷…" with the spaces gone. The app does what the expression meant:

- `prepareTex` drops the invisible characters, turns the typed signs into commands, wraps a run of two or more letters (and the spaces and hyphen inside it) in `\text{}` (a single letter stays a variable, `r-g` stays a subtraction), and escapes a bare `%`.
- `splitPieces` cuts the prepared LaTeX after each top-level `=` / operator (never inside brackets or text) and `_Lines` draws each piece with TeX's space put back by hand (5/18 em round a relation, 4/18 round an operator) in a `Wrap`: a long formula sets over several lines, a short one is one line. (`flutter_math_fork`'s own `texBreak` drops the space at the cut, so it is not used.)
- LaTeX the renderer cannot read, or an expression that is not LaTeX, is shown as **plain text** (`plainFormula`), never as an error.
- The note is read as variables when every line is `symbol = meaning`; otherwise it is shown as prose.
- All 87 recorded formulas parse and draw (`all 87 recorded formulas are drawn as math…`; the live test does the same over whatever the API holds).

## What the API or the app cannot do, and what the screen does instead

| Wanted | Reality | The screen |
| --- | --- | --- |
| "Known / still learning" kept between visits | the API has no place for it, and the app has no key-value store (`shared_preferences` is not a dependency) | **Session only**: the marks live in the controller for as long as the study screen is open (the summary, "study the rest" and the tally read them); the **star** is the API's and is kept. |
| A plan check before a deck takes a place | opening a deck takes one for good; there is no "peek" | the grid shows the line (N used) and the lock before the tap; the tap itself is the website's behaviour. |
| Search over the cards of every deck | the list returns counts, not cards (the website's deck search is over titles and descriptions too) | the deck search narrows by title and description; inside a deck the category chips narrow it. |
| A formula with a separate "variables" field | there is none; the symbols are in the note, the figures in the example | the note as the **Where** list when it reads `symbol = meaning`, and each example's **Given** figures. |
| Read aloud / autoplay / fullscreen of the website's deck | browser features | not drawn (a speaker that does nothing would be a dead control). |
| A downloadable formula sheet | none | Copy puts the formula on the clipboard. |
| The source's NPV formula | stored garbled (`NPV=t=1∑n​(1+r)tCFt​​−Initial Investment`, pasted from a rendered equation, which lost the fraction and the limits) | drawn as typed (the website draws it worse); the content owner's to correct.
