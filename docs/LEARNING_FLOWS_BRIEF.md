# The Learning tab as the Learning Center: the doors and their whole flows

The owner's words, 23 Oct 2026: "Learning consists of Assess Your Knowledge, Mock Tests, Flash Cards, like that. Not the implemented way. Observe the design and change and implement the complete flow." The tab so far is only a catalogue of courses (a grid of cards). It must be the **Learning Center** the website has: a hub of doors, each a complete flow that works against the API.

There is no PNG for these screens. **The reference is the website's Learning Center** (read it: it is the product's design) plus the app's own design language (below). Where the website is a wide desktop page, do what a phone app does with the same content and the same steps.

## The doors (the hub's tiles, in this order: `frontend/src/features/learning/data/hub.ts`)

| Door | Website route | What it is | Builder |
|---|---|---|---|
| Assess Your Knowledge | `/learning/assessment` | Short topic-based quizzes per certification programme and level, before the real certification | landing: ASSESS; engine: EXAM |
| Mock Exams | `/learning/mock-tests` | Full-length competition papers by topic, three sets each, unlimited attempts | landing: ASSESS; engine: EXAM |
| Flash Cards | `/learning/flash-cards` | Key terms and questions as cards: read the front, flip for the answer | STUDY |
| Knowledge Center | `/learning/formulas` | The calculations an FM works from, each with its expression and worked numbers | STUDY |
| ICR Courses | `/learning/professional-development` | ICR's own courses, enrol on a batch | HUB (exists: the grid + the course sheet in `lib/features/learning/`) |
| Partner Courses | `/learning/partners` | Awarding bodies and institutes, then each one's catalogue | HUB |

Also on the website's Learning dashboard (`frontend/src/components/learning/dashboard/LearningDashboard.tsx`): the member's own places: their enrolments, attempts, certificates, knowledge gaps. The hub shows a "My learning" strip for them.

## Who builds what, and the doors' contracts

Every screen below is `ConsumerWidget`-free plain Flutter + `provider`, like the rest of the app (`docs/SCREEN_BUILD_CHECKLIST.md`, `docs/DESIGN_REPLICATION.md`). **Each public entry screen builds its own controller** (repository = `AppConfig.demo ? Demo…Repository() : Api…Repository(api: context.read<ApiClient>())`) inside the screen, because a pushed route does not inherit the tab's providers; the hub just pushes it. A demo repository (a little sample content) is required so `--dart-define=FEED_SOURCE=demo` does not break; it does not need to be elaborate.

1. **HUB** owns `lib/features/learning_hub/**` and `lib/features/learning/**` (the existing catalogue grid and course sheet) and the `learning:` tab line in `lib/app.dart` (the only app.dart edit allowed, to mount `LearningHubScreen`).
   - `LearningHubScreen({required VoidCallback onBack})`: the tab. Header as the other tabs (TitleBar "Learning" + bell, search), a "My learning" strip (the member's enrolments / attempts / certificates counts, opening `MyAttemptsScreen`, `CertificatesScreen`, the My courses grid), the six doors as artwork tiles in a two-column grid (title, one line of what it is, a CTA; the website's hub tiles use the images in `frontend/public/` — find the learning artwork there, copy what you need into `assets/images/demo/learning/` and register it in `pubspec.yaml`... the pubspec asset dirs already list `assets/images/demo/learning/`), then "ICR Courses" and "Partner Courses" rails (cards), as the website's dashboard.
   - ICR Courses door: the existing catalogue grid screen (`LearningScreen`), now pushed. Partner Courses: `PartnerCoursesScreen` (institutes grid from `GET /learning/providers`) → `PartnerScreen` (one institute: summary, its courses as the same grid cards, "Ask the institute" = `POST /learning/providers/:slug/enquire`).
   - Pushing: `AppShell.push(context, (c) => ShellPage(tab: AppTab.learning, child: <screen>(onBack: () => Navigator.of(c).pop())))`, as `lib/app_screens.dart` does for Events; tab: `AppTab.learning`. The hub opens `AssessmentScreen`, `MockTestsScreen`, `FlashCardsScreen`, `KnowledgeCenterScreen`, `MyAttemptsScreen`, `CertificatesScreen` through these constructors (stubs exist now, `lib/features/learning_*/…`; the other builders replace their files).
2. **EXAM** owns `lib/features/learning_exam/**` (models, repository, controllers, screens) and `tool/seed/learning-flows.ts`.
   - `Future<void> openPaper(BuildContext context, PaperRef paper)` in `open_paper.dart` (keep `PaperRef` and this signature): the paper's **brief** sheet (what it is: questions, time limit, pass mark, attempts used of the limit, the best score; what it takes to open it: held / included in the plan / credits (`redeem`) / price (opens the website's page); a Start/Resume/Retake button), then the **exam** as a full-screen route with **no tab bar** (`Navigator.push`, not `AppShell.push`), then the **result**. Exam: the question (single choice, multiple choice, whatever types the API has: `GET /learning/papers/:slug` returns the full set; read the DTOs), options, a progress bar and "N of M", the countdown from the paper's time limit (the attempt is submitted when it reaches zero), previous/next, flag for review, a question palette sheet, "Submit" with an overview ("12 answered, 3 skipped, 2 flagged") and a confirm; leaving mid-exam asks first; the answers are kept if the app is backgrounded (a restored in-memory state is enough; do not lose answers on rotation or a rebuild). Submit = `POST /learning/papers/:slug/attempts` (read `SubmitAttemptDto`); the **result** shows the score, percentage, pass/fail against the pass mark, a per-topic breakdown if the API returns one, the review of each question with the right answer and the explanation if the API gives them, a certificate button when `certificateEnabled` and earned, and "Retake" / "Back".
   - `MyAttemptsScreen({required VoidCallback onBack})` (`GET /learning/me/attempts`, `/me/attempts/:id` for the result again) and `CertificatesScreen({required VoidCallback onBack})` (`GET /learning/me/certificates`, `/learning/certificates/:certificateId`: show the certificate on screen like `Certificate.tsx`, share its public link `/learning/certificates/<id>` and the verify page; the downloadable PDF stays English per the owner and is opened on the website).

## Design language (no PNG: match the app)

Reuse `lib/core/widgets/` (TitleBar, search field, chips, section heading, buttons, `showDetailSheet`), `lib/core/theme/` and the card frame of the Learning catalogue grid (`lib/features/learning/widgets/course_card.dart`, itself measured from the Events agenda and Find Mentors cards): white cards, 1 dp `#E2E8F0`-style border, the soft shadow, 10–12 dp radius, cover on top with a pill, Work Sans titles, IBM Plex Sans body. Colours from `AppColors`; the accent blue, success green for passed/known, the error red for failed. Two columns where the content is a card; single column for questions and results. Text sized for a phone (body 14–16, tap targets 48 dp). Every list has a loading skeleton or spinner, an empty state and an error state with "Try again" (the other screens' patterns). Light mode only (the rest of the app is light). Set `Semantics` on the exam's options and the flip card.
